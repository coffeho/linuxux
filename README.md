Автоматизация Python-проекта с помощью GNU Make
Данный проект демонстрирует построение воспроизводимого и независимого от состояния системы (stateless) конвейера автоматизации. Вместо ручной активации виртуальных окружений используется Makefile как единая точка входа.

Проект спроектирован по принципу By-design, not by-mistake: изоляция гарантирована явными путями, а Git-репозиторий остается абсолютно чистым.

1. Структура проекта и чистота Git
Plaintext
makepractise/
├── .gitignore       # Исключает .venv и кэш инструментов
├── Makefile         # Сценарий автоматизации и граф зависимостей
├── pyproject.toml   # Конфигурация проекта и зависимостей (PEP 621)
├── README.md        # Эта документация
└── src/
    ├── app.py       # Точка входа
    ├── calc.py      # Проверка типов (MyPy)
    ├── example.py   # Форматирование (Black)
    └── service.py   # Анализ импортов
Правильно настроенный .gitignore гарантирует, что после сборки, форматирования и запуска тестов команда git status возвращает чистый рабочий каталог (working tree clean).

2. Изоляция окружения (Stateless подход)
Проблема
Команда source .venv/bin/activate ненадежна в Makefile, так как GNU Make выполняет каждую строчку рецепта в отдельном процессе Shell. Настройки окружения теряются между строками.

Решение
Мы полностью отказываемся от "активации". В Makefile прописаны явные пути к бинарникам внутри локального venv:

Makefile
VENV_DIR := .venv
PYTHON   := $(VENV_DIR)/bin/python
PIP      := $(VENV_DIR)/bin/pip
MYPY     := $(VENV_DIR)/bin/mypy
BLACK    := $(VENV_DIR)/bin/black
Это гарантирует использование проектного окружения вместо системного.

3. Граф зависимостей (Цепочки задач)
Команда make check объединяет все проверки в единый конвейер. Make автоматически строит граф зависимостей: перед проверками он проверяет наличие venv и актуальность установленных пакетов.

Plaintext
               [ make check ]
                     │
     ┌───────────────┼────────────────┐
     ▼               ▼                ▼
[ typecheck ]     [ lint ]    [ check-requirements ]
     │               │                │
     └───────────────┼────────────────┘
                     ▼
                [ install ]
                     │
                     ▼
                  [ venv ]
4. Контроль качества (QA)
Проверка импортов (make check-requirements): Сверяет используемые в src/service.py пакеты (requests, numpy, fastapi) с объявленными в pyproject.toml.

Проверка типов (make typecheck): Запускает mypy. Позволяет обнаружить передачу неверных типов в src/calc.py до этапа выполнения.

Разделение форматирования:

make lint — только проверяет код на соответствие стилю (black --check), ничего не изменяя (для CI/CD).

make format — автоматически исправляет стиль и форматирует код в src/example.py.

5. Быстрый старт для ревьюера
Выполните в терминале:

Bash
# 1. Посмотреть доступные команды
make help

# 2. Запустить весь конвейер (создаст venv, поставит зависимости и запустит проверки)
make check

# 3. Запустить приложение гарантированно внутри venv
make run

# 4. Автоматически исправить форматирование кода
make format

# 5. Полная очистка проекта от venv и кэша
make clean
